## 透明网关

Memory Router 位于您的应用与模型厂商之间。您的应用与 Router 的交互方式和直连模型厂商完全一致——同样的载荷、同样的 SDK、同样的响应结构——Router 在中途透明地加上一层记忆。

因为 Router 使用与您的模型厂商相同的协议，接入它只需**更换 base URL 加上一个 `boundary_id` 查询参数**。代码的其他部分都不用动。

## 三个步骤

<Steps>
<Step title="拦截">
您的应用把请求发给 Memory Router 而不是模型厂商——同样的载荷、同样的 SDK、同样的响应结构。URL 上的 `boundary_id` 告知 Router 这段会话属于哪个记忆范围。
</Step>

<Step title="召回">
Router 在该 Boundary 的范围内检索历史记忆，只把相关上下文注入提示词。
</Step>

<Step title="转发">
增强后的请求发往模型——可以是您自己的模型厂商（BYOK），也可以是 MemoryLake 托管模型。
</Step>
</Steps>

## Boundary 定义范围

每个启用记忆的请求都带有 `boundary_id`。**Boundary** 将会话绑定到一个工作空间、一个或多个项目、一个人类 Actor 和一个助手 Actor——这样 Router 就能准确知道该读谁的记忆。

- 一个用户对一个助手？一个 Boundary。
- 同一个产品服务大量用户？为每个用户（或每个用户—助手组合）建一个 Boundary，记忆就绝不会在用户之间泄漏。
- **不带** `boundary_id` 的请求会完全跳过记忆层，直接透传给模型。
- [图像生成](/features/memory-router/image-generation)请求不使用记忆：`boundary_id` 只适用于 Chat Completions、Responses 和 Messages。

<Info>
Memory Router 只**读取**记忆，不会从您的请求或模型的回复中提取或存储任何内容。要添加记忆，请在控制台把文件上传到项目，或通过 [MemoryLake API](/features/memorylake/api-reference/core-memory/overview) 写入。
</Info>

## 共享记忆池

Router 与 [MemoryLake API](/features/memorylake/overview) 和控制台读取同一个记忆池。在那里添加的记忆，会在使用对应 Boundary 的 Router 调用中被召回——跨会话、跨应用、跨模型都只有一个真实来源。
