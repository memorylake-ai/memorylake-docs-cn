---
title: "通过 MCP 连接"
description: "用标准 OAuth2 将 Claude Code、Codex、Cursor 等 MCP 客户端连接到 MemoryLake"
---

MemoryLake 运行着一个**远程 MCP 服务器**，任何支持 MCP 的客户端都可以通过 HTTP 连接。授权采用标准 **OAuth2**——您无需把任何密钥粘贴到配置文件中，并可在授权页面选择该客户端可访问的工作空间和 Boundary。

## 服务器 URL

```text
https://app.memorylake.cn/memorylake/mcp/v2
```

中国站已启用该端点，**无需在控制台预先开通**——直接把客户端指向上面的 URL，首次连接时完成 OAuth 授权即可。

<Info>
连接页面不带作用域：没有项目选择器。个人/团队、工作空间和 Boundary 都在 OAuth 授权页面上选择，并在授权时写入令牌。要换到别的作用域，需要在客户端中移除并重新添加这个 MCP Server，再授权一次（见下方[管理访问权限](#管理访问权限)）。
</Info>

在控制台中，打开任意工作空间的 **MCP** 标签页，可以看到同样的分客户端接入指引（「接入 MemoryLake MCP」）。旧入口「集成 → MCP」会自动跳转到这里。

## 连接您的客户端

每个客户端都分三步：添加 MCP Server、在浏览器完成授权、验证连接。授权页会依次让您：用 MemoryLake 账号登录（已登录则跳过）、选择个人/团队、选择工作空间与 Boundary。

<Tabs>
<Tab title="Claude Code">
**1. 添加 MCP Server**：在终端运行：

```bash
claude mcp add --transport http memorylake https://app.memorylake.cn/memorylake/mcp/v2
```

**2. 在浏览器完成授权**：在终端运行 `claude` 进入会话，输入 `/mcp`，选中 `memorylake` 后选择 **Authenticate**，浏览器会打开授权页。Claude Code 没有独立的登录命令，授权只能在会话内触发。

**3. 验证连接**：

```bash
claude mcp list
```

输出里 `memorylake` 一行应显示 `✓ Connected`；若显示 `! Needs authentication`，说明第 2 步的授权还没完成。
</Tab>

<Tab title="Codex">
**1. 添加 MCP Server**：在终端运行：

```bash
codex mcp add memorylake --url https://app.memorylake.cn/memorylake/mcp/v2
```

这条命令会把下面的配置写进 `~/.codex/config.toml`（也可以手动添加）：

```toml
[mcp_servers.memorylake]
url = "https://app.memorylake.cn/memorylake/mcp/v2"
```

服务名可以自定义，但后面的登录命令要跟着改。

**2. 在浏览器完成授权**：

```bash
codex mcp login memorylake
```

**3. 验证连接**：运行 `codex mcp list`，`memorylake` 应显示为已连接。
</Tab>

<Tab title="Cursor">
**1. 添加 MCP Server**：在控制台工作空间的 **MCP** 标签页点击 **一键装进 Cursor**，或手动把下面的配置写进 `~/.cursor/mcp.json`（全局可用）或项目里的 `.cursor/mcp.json`（只对该项目生效）：

```json
{
  "mcpServers": {
    "memorylake": {
      "url": "https://app.memorylake.cn/memorylake/mcp/v2"
    }
  }
}
```

保存后 Cursor 会自动重新加载。

**2. 在浏览器完成授权**：打开 Settings → MCP，`memorylake` 会提示需要登录；点击登录，浏览器会打开授权页。

**3. 验证连接**：回到 Settings → MCP，`memorylake` 应显示为已连接并列出可用工具。
</Tab>

<Tab title="VS Code">
**1. 添加 MCP Server**：在控制台工作空间的 **MCP** 标签页点击 **一键装进 VS Code**，或手动把下面的配置写进工作区的 `.vscode/mcp.json`（只对该项目生效），也可以用命令面板执行 `MCP: Add Server`：

```json
{
  "servers": {
    "memorylake": {
      "type": "http",
      "url": "https://app.memorylake.cn/memorylake/mcp/v2"
    }
  }
}
```

**2. 在浏览器完成授权**：启动该服务器时 VS Code 会提示授权，确认后浏览器会打开授权页。

**3. 验证连接**：在 MCP 服务器列表里，`memorylake` 应显示为运行中。
</Tab>

<Tab title="Claude Desktop">
**1. 添加 MCP Server**：打开 Settings → Connectors → Add custom connector，把上面的服务器 URL 粘贴进去。

**2. 在浏览器完成授权**：确认添加后 Claude Desktop 会弹出授权窗口，按提示完成登录与授权。

**3. 验证连接**：回到 Connectors 列表，`memorylake` 应显示为已连接，对话里即可看到它的工具。
</Tab>

<Tab title="其他客户端">
任何支持 OAuth 2.1 的远程 MCP 客户端都能接入——把上面的服务器 URL 填进客户端即可，不需要 API Key，也不需要自定义 header。其余步骤由客户端自动完成：

- 首次调用收到 401 后，从站点根路径的 `.well-known` 自动发现授权服务器
- 通过动态客户端注册（DCR）加 PKCE 走浏览器授权，无需预先配置 `client_id`
- 拿到令牌后自动携带，过期由 refresh token 自动续期
</Tab>
</Tabs>

## 已连接客户端能做什么

授权完成后，客户端将获得用于搜索和分析作用域内内容的工具：

| 工具 | 功能 |
|---|---|
| `search_memory` | 在记忆和文档中执行关键词 + 语义混合搜索 |
| `fetch_memory` | 获取特定结果的详细元数据与下载链接 |
| `get_memorylake_metadata` | 概览——按类型统计文件数、电子表格的 sheet 名称、文档统计 |
| `create_memory_code_runner` / `run_memory_code` | 沙箱化 Python（pandas、numpy 等）处理作用域内的文件，状态在多次调用间保持 |

OpenAI 协议的客户端会自动获得这些工具的简化版 `search` / `fetch` 变体——同一个端点自适应不同客户端。

这些工具只做读取与分析；它们不会修改或删除您的文档和记忆。

## 管理访问权限

- **换工作空间或 Boundary**：个人/团队、工作空间和 Boundary 在授权时写入令牌，事后改不了。在客户端里删掉这个 MCP Server 再重新添加，然后重新授权一次，即可选择新的作用域。以 Claude Code 为例，执行下面两条命令后，在会话里用 `/mcp` 重新 Authenticate：

  ```bash
  claude mcp remove memorylake
  claude mcp add --transport http memorylake https://app.memorylake.cn/memorylake/mcp/v2
  ```

- **撤销授权**：在控制台 **账号设置 → 登录与安全 → 已授权的应用** 中撤销该客户端。撤销后该客户端的刷新令牌和已持有的访问令牌立即失效，要再使用需要在客户端里重新授权。如需同时从客户端移除，Claude Code 执行 `claude mcp remove memorylake`。
- **Token 有效期**：访问 token 生命周期很短，由客户端自动刷新。

<Note>
早期版本的 MemoryLake 使用 v1 MCP 端点，需要把项目级 Key 嵌入 URL（`…/mcp/v1?apikey=…`）。该方式已从控制台下线，改用 OAuth2。v1 端点仍保留以兼容旧集成，但新集成应使用上面的 v2 URL。
</Note>

## 故障排查

<AccordionGroup>
<Accordion title="客户端无法连接">
确认 URL 以 `/mcp/v2` 结尾，且客户端配置的是**远程 HTTP** MCP 服务器（而不是本地命令）。同时确认客户端支持 MCP 的 OAuth2——只接受静态 token 的旧客户端无法使用 v2 端点。
</Accordion>

<Accordion title="授权成功但看不到工具">
检查是否在授权页面完成了工作空间和 Boundary 的选择。重新执行客户端的 MCP 登录再试一次。
</Accordion>

<Accordion title="工具没有返回任何结果">
授权的作用域可能指向了一个空项目。请在控制台确认您所选的工作空间和项目中确实有文档或记忆。
</Accordion>

<Accordion title="浏览器没有自动弹出授权页">
终端会打印一条包含 `/oauth2/mcp/authorize` 的链接，手动复制到浏览器打开即可。SSH 或远程开发环境基本都是这种情况。
</Accordion>

<Accordion title="一直提示 401 / Unauthorized">
多半是令牌过期或已失效，重新授权一次即可。Claude Code：在会话里输入 `/mcp`，选中 `memorylake` 后重新 Authenticate。Codex：运行 `codex mcp login memorylake`。其他客户端在各自的 MCP 设置里重新登录。
</Accordion>

<Accordion title="我的控制台里看不到 MCP">
工作空间的 **MCP** 标签页与 MCP 服务端由同一个开关控制。如果看不到该标签页，或页面提示「当前部署未启用 OAuth2 MCP」，说明您所在的环境没有启用 OAuth2 MCP（私有化部署的功能集由部署方配置决定），请联系您环境的管理员或商务确认。
</Accordion>
</AccordionGroup>
