### 您自己的标识符

您创建的每个资源都有两个标识符。`id` 由平台铸造——前缀加 32 位十六进制，形如 `actor-7b5470549febfaca2acc5a3ebcaa2138`。`custom_id` 则是您带来的：这个东西在**您自己系统里已有的标识符**。

设置它，意味着您不必在自己的记录旁边再存一份我们的 id。用您应用里已有的用户 ID 创建 Actor，此后就能直接用它寻址：

```bash
# 用您系统里已有的 ID 创建
curl -X POST .../api/v3/actors \
  -d '{"custom_id": "user-4471", "display_name": "Jane"}'

# 之后带 by_custom_id=true 即可用它访问
curl .../api/v3/actors/user-4471?by_custom_id=true
```

<Note>
  **`custom_id` 在您的租户内必须唯一**，按资源种类计——两个 Actor 不能共用一个，但一个 Actor 和一个项目可以。删除资源后，它的 `custom_id` 可以重新使用。
</Note>

## API 概览

MemoryLake API 让你将文档和对话导入项目，自动提取结构化事实，并使用自然语言搜索所有记忆来源。用它来构建具有长期记忆的 AI 应用。

## 基础 URL

```
https://app.memorylake.cn/openapi/memorylake
```

## 认证

所有 API 请求都需要在 `Authorization` 头中提供 Bearer 令牌。详情请参阅[认证](/features/memorylake/api-reference/authentication)。

## 通用模式

### 响应格式

所有响应遵循以下结构：

```json
{
  "success": true,
  "message": "Operation completed successfully",
  "data": {
    // 响应数据
  }
}
```

错误响应：
```json
{
  "success": false,
  "message": "Error description",
  "error_code": "ERROR_CODE"
}
```

### 分页

列表接口使用 continuation-token 分页：

**查询参数**：
- `page_size`：每页条数
- `continuation_token`：上一次响应返回的令牌，用于获取下一页

当响应中没有 `continuation_token` 时，表示没有更多页。

### 幂等请求

会改动团队的写接口（创建 Key、轮换 Key、邀请成员、修改角色等）支持可选的 `Idempotency-Key` 请求头，取值为任意唯一字符串，例如 UUID。24 小时内用同一个值重试，会重放第一次的响应（包括错误），而不会再执行一次改动；重放的响应带有 `Idempotency-Replayed: true`。同一个值配不同的参数，或在第一次请求尚未完成时重复使用，会被拒绝。新 API Key 这类密钥只在第一次的响应里返回。支持该请求头的接口会在**请求头**一节列出它。

```bash
curl -X POST 'https://app.memorylake.cn/openapi/memorylake/admin/v1/api-keys/{id}/rotate' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Idempotency-Key: 7c1d2e3f-0a9b-4c8d-b7e6-f5a4d3c2b1a0'
```

### 时间戳

所有时间戳使用 ISO 8601 格式：
```
2024-01-15T10:30:00Z
```

标注为「Unix 秒级时间戳」的字段（例如团队、成员、用量和计费接口中的时间）是整数，表示自 1970-01-01 UTC 起的秒数。
