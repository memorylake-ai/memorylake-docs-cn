---
title: "设置用户组访问范围"
description: "按所列资源类型，替换用户组为其成员提供访问的实例"
---

```
PUT /openapi/memorylake/admin/v1/access-groups/{group_id}/access-scope
```

按所列资源类型，替换用户组为其成员提供访问的实例。用户组只增加访问权限：`all` 模式会从用户组中移除该类型的实例，且不限制任何人。项目实例需要提供其 `workspace_id`。响应为[获取用户组访问范围](/features/memorylake/api-reference/access-control/get-access-group-access-scope)返回的范围，因此还需要 `view` 权限。

响应携带 `ETag` 头（与对该资源执行 GET 时返回的值相同）。将其放入 `If-Match` 回传即可使写入成为条件写入：若资源在此期间已被修改，写入将以 412 被拒绝，且不做任何更改。该校验能缩小但无法完全消除并发覆盖的窗口——两个在同一时刻通过校验的写入方都可能写入成功。

<Note>
**所需权限：** `access_group:manage` 且 `access_group:view`

- 如果改动会让某人获得管理员角色，或会缩小管理员能访问的范围，还需要由团队所有者或管理员操作。
</Note>

### 路径参数

<ParamField path="group_id" type="string" required>
标识符
</ParamField>

### 请求头

<ParamField header="If-Match" type="string">
可选。先前读取此资源时获得的 ETag。若资源此后已变更，写入将以 412 拒绝；省略则无条件覆盖。
</ParamField>

### 请求体

<ParamField body="reason" type="string" required>
变更原因；记录在审计日志中
</ParamField>

<ParamField body="scopes" type="array" required>
所列每种资源类型的实例列表替换为给定列表；`mode` 为 `all` 时移除该类型的实例（用户组从不限制任何人）。未列出的类型保留当前列表。
<Expandable title="Access Scope Entry 对象">
  <ParamField body="scopes[].mode" type="string" required>`all` 表示所有实例；`instances` 表示仅列出的实例</ParamField>
  <ParamField body="scopes[].resource_type" type="string" required>资源类型，例如 `memorylake:project`</ParamField>
  <ParamField body="scopes[].instances" type="array">
  当 `mode` 为 `instances` 时必填
  <Expandable title="Access Scope Instance 对象">
    <ParamField body="scopes[].instances[].id" type="string" required>实例 ID</ParamField>
    <ParamField body="scopes[].instances[].actions" type="array">省略则为该成员角色允许的所有操作</ParamField>
    <ParamField body="scopes[].instances[].via_permission_level" type="boolean">只读行的回显。标记为 `true` 的实例在写入时会被跳过——权限级别在资源上设置，而非通过访问范围设置。</ParamField>
    <ParamField body="scopes[].instances[].workspace_id" type="string">父工作空间——项目实例必填</ParamField>
  </Expandable>
  </ParamField>
</Expandable>
</ParamField>

<RequestExample>
```bash cURL

  -H 'Content-Type: application/json' \
  -d '{
    "reason": "example",
    "scopes": [
      {
        "mode": "all",
        "resource_type": "example",
        "instances": [
          {
            "id": "185afe41ca6ac4566fdc7a9adeabf5a0",
            "actions": [],
            "via_permission_level": false,
            "workspace_id": "12404b77739317d2b08fc918a95f0be9"
          }
        ]
      }
    ]
  }'
```
</RequestExample>

  <ResponseField name="group_id" type="string">用户组</ResponseField>

      <ResponseField name="workspace_id" type="string">项目实例的父工作空间。写入项目实例时必填。</ResponseField>
    </Expandable>
    </ResponseField>
  </Expandable>

### 错误

出错时返回 `success: false`、`message` 和 `error_code`。全部错误码见[错误码](/features/memorylake/api-reference/errors)。

| 状态码 | 含义 |
| --- | --- |
| `400` | 参数或请求体无效 |
| `401` | API Key 缺失、无效、已停用或已过期 |
| `403` | 该 Key 无权执行此操作 |
| `404` | 资源不存在 |
| `409` | 请求与当前状态冲突，例如重复或已达上限 |
| `412` | `If-Match` 不再匹配：读取之后资源已被修改 |
| `422` | 请求体或参数未通过校验 |
| `429` | 请求过多，请按 `Retry-After` 等待后重试 |
| `500` | 服务端错误 |
| `503` | 暂时不可用，请稍后重试 |
