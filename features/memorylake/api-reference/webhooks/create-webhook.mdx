---
title: "添加 Webhook"
description: "添加一个接收所选团队事件的接收地址"
---

```
POST /openapi/memorylake/admin/v1/webhooks
```

添加一个接收所选团队事件的接收地址。响应中带有签名密钥——这是唯一一次显示。请求按 Standard Webhooks 方式签名（`webhook-id`、`webhook-timestamp`、`webhook-signature`）。接收地址必须以 https:// 开头并解析到公网地址；每个团队最多 10 个 Webhook。

<Note>
**所需权限：** `webhook:manage`
</Note>

### 请求体

<ParamField body="url" type="string" required>
接收地址。必须以 https:// 开头，且不能解析到内网、本机或保留地址。
</ParamField>

<ParamField body="all_events" type="boolean">
发送全部事件类型，包括以后新增的类型
</ParamField>

<ParamField body="description" type="string">
说明，最多 100 个字符
</ParamField>

<ParamField body="events" type="array">
要发送的事件类型（见[列出事件类型](/features/memorylake/api-reference/webhooks/list-webhook-event-types)）。`all_events` 不为 true 时必填；不认识的类型会被忽略。
</ParamField>

<RequestExample>
```bash cURL
curl -X POST 'https://app.memorylake.cn/openapi/memorylake/admin/v1/webhooks' \
  -H 'Authorization: Bearer sk_xxxxxx' \
  -H 'Content-Type: application/json' \
  -d '{
    "url": "https://example.com/url",
    "all_events": false,
    "description": "Example description",
    "events": [
      "example"
    ]
  }'
```
</RequestExample>

### 错误

出错时返回 `success: false`、`message` 和 `error_code`。全部错误码见[错误码](/features/memorylake/api-reference/errors)。

| 状态码 | 含义 |
| --- | --- |
| `400` | 参数或请求体无效 |
| `401` | API Key 缺失、无效、已停用或已过期 |
| `403` | 该 Key 无权执行此操作 |
| `404` | 资源不存在 |
| `409` | 请求与当前状态冲突，例如重复或已达上限 |
| `422` | 请求体或参数未通过校验 |
| `429` | 请求过多，请按 `Retry-After` 等待后重试 |
| `500` | 服务端错误 |
