## 403 会告诉您什么

权限拒绝带的信息不止一个错误码。除了 `error_code: ACCESS_DENIED`，`data` 里还会写明**缺的是哪个权限**、以及**授予什么就能通过**，您不必靠猜：

```json
{
  "success": false,
  "message": "You don't have the \"Modify Library Item\" permission. Ask a team owner or admin to grant it.",
  "error_code": "ACCESS_DENIED",
  "data": {
    "denied": [
      {
        "permission": "drive:item_modify",
        "permission_level": "service",
        "resource_type": "drive"
      }
    ],
    "stage": "capability",
    "required_any_of": [
      { "key": "pkg:library:write", "resource_type": "library" }
    ]
  }
}
```

<ResponseField name="data.denied" type="array">
  被检查且未持有的权限。`permission` 就是需要授予的标识符；`permission_level` 说明它是整个服务授予一次，还是按资源实例逐个授予。
</ResponseField>

<ResponseField name="data.stage" type="string">
  决定您该向管理员提哪种请求。`capability` —— 去要这项权限本身；您在任何地方都没有它，只放开这一个资源是不够的。`instance` —— 去要这个资源的访问范围；这项权限您在别处已经有了。
</ResponseField>

<ResponseField name="data.required_any_of" type="array">
  其中**任意一项**授予了就能通过。把它交给管理团队权限的人，这是「我需要什么」最短的答案。
</ResponseField>

<Note>
  拒绝不会告诉您资源是否存在——`403` 只表示「不给您」，不含别的信息。删除也一样：先检查权限。权限通过后，删除已被删掉或本来就不存在的资源都返回 `200`，所以重复删除可以安全重试。如果您能删除某个资源，靠的只是单独授予在这个资源上的权限（而不是您的角色），这项授权会随资源一起删除，再删一次就会返回 `403`。删除不存在的知识条目目前返回 `400`。
</Note>

在团队、成员、邀请、API Key、访问控制、用量、计费与 IM 集成接口上，缺少权限时返回 `403`、`ACCESS_DENIED` 和消息 `permission denied`，不带 `data` 对象；每个接口所需的权限写在该接口的页面上。

### 为保护管理员而拒绝

有些改动会让某人获得管理员角色，或减少管理员的访问权限。这类改动只能由团队所有者或管理员执行；其他人会收到 `403` 和 `ACCESS_DENIED`，此时 `data.operation` 给出的是被拒绝的改动类型，而不是缺少的权限：

```json
{
  "success": false,
  "message": "only an owner or admin may change an admin's role",
  "error_code": "ACCESS_DENIED",
  "data": { "operation": "change_role" }
}
```

`operation` 的取值为 `change_role`、`remove_member`、`remove_group_member`、`delete_group`、`reduce_admin_role_rules`、`narrow_admin_role_scope`、`narrow_admin_member_scope`、`downgrade_admin_member_tier`、`narrow_admin_via_group` 或 `remove_admin_member_rule`，今后可能增加。

## HTTP 状态码

| 状态码 | 含义 | 常见原因 |
|--------|------|----------|
| 200 | 成功 | 请求成功完成 |
| 201 | 已创建 | 资源创建成功 |
| 400 | 错误请求 | 参数无效或请求格式错误 |
| 401 | 未授权 | API 密钥缺失或无效 |
| 402 | 需要付款 | 此操作的配额不足 |
| 403 | 禁止访问 | 认证有效但权限不足 |
| 404 | 未找到 | 资源不存在 |
| 409 | 冲突 | 请求与当前状态冲突，例如名称重复或已达上限 |
| 412 | 前置条件失败 | `If-Match` 的值已不匹配：您读取之后资源被改过 |
| 422 | 无法处理 | 请求体或参数未通过校验 |
| 429 | 请求过多 | 超出速率限制 |
| 500 | 服务器内部错误 | 服务端错误 |
| 502 | 网关错误 | API 背后的服务无法连接，请稍后重试 |
| 503 | 服务不可用 | 依赖服务暂时不可用，请稍后重试 |

## 错误响应

当请求失败时，API 会返回结构化的错误体以及 HTTP 状态码。`error_code` 字段标识具体错误，便于程序化处理：

```json
{
  "success": false,
  "message": "Human-readable error description",
  "error_code": "ERROR_CODE"
}
```

所有 MemoryLake API 接口都按这一格式返回错误，包括请求到达服务之前就被拒绝的情况：API Key 缺失或无效（`401`）、Key 从不被允许的地址调用（`403`）、超出速率限制（`429`）、服务无法连接（`502`）以及维护中（`503`）。唯一的例外是 [Memory Router](/features/memory-router/api-reference/overview) 的推理端点：它们保持模型厂商的格式。就某个请求联系支持团队时，请提供它的 `X-Trace-ID` 响应头。

<Note>
2026 年 10 月之前，上述拒绝使用的是另一种响应体 `{"error": {"message", "type"}}`。如果您的代码读取的是 `error.message`，请改为读取 `message` 和 `error_code`。
</Note>

## 错误代码

| 错误代码 | 描述 |
|----------|------|
| `NOT_FOUND` | 资源未找到 |
| `DRIVE_ITEM_CONFLICT` | 文件库项名称冲突，例如已存在同名的文件或文件夹 |
| `INVALID_ARGUMENT` | 无效输入：参数校验失败、类型不匹配或请求体格式错误 |
| `CONNECTOR_NOT_LINKED` | 第三方连接器（WPS、飞书等）尚未授权 |
| `STATE_NOT_READY` | 资源存在但当前状态不允许执行此操作 |
| `ACCESS_DENIED` | 调用方无权访问该资源 |
| `QUOTA_EXCEEDED` | 配额或使用限制已超出 |
| `RATE_LIMIT_EXCEEDED` | 请求过多。请按 `Retry-After` 响应头等待后重试，详见[速率限制](/features/memorylake/api-reference/rate-limits) |
| `SERVICE_UNAVAILABLE` | 服务暂时不可用，例如正在维护。请稍后重试；已知需等待的时长时会返回 `Retry-After` |
| `DATASET_TABLE_LIMIT_EXCEEDED` | NL2SQL 数据集中的表数量超过允许上限 |
| `DB_CONNECTION_FAILED` | 无法用所给的连接参数连上数据库：主机不可达、凭据被拒绝，或数据库不存在。用同样的参数重试不会成功 |
| `RESOURCE_LIMIT_EXCEEDED` | 超出了为您账户配置的数量上限，例如一个工作空间内的项目数，或一次请求中 `project_ids` 的个数 |
| `DOWNLOAD_NOT_SUPPORTED` | 请求的资源不支持下载 |
| `UNAUTHORIZE` | 需要认证 |
| `CONNECTOR_UNAUTHORIZE` | 连接器未授权 |
| `CUSTOM_ID_CONFLICT` | 已存在使用该 `custom_id` 的资源 |
| `BINDING_ALREADY_EXISTS` | 该绑定关系已存在 |
| `RESOURCE_IN_USE` | 资源仍被其他资源引用，需先解除引用才能删除，例如仍有数据源的数据库连接，或仍被数据库记忆绑定的分析模型 |
| `SKILL_NAME_CONFLICT` | 您的租户内已有同 `name` 的技能 |
| `SKILL_NOT_USABLE` | 创建 Agent 或 Agent 版本时引用的技能未通过安全审核、不存在或还没有技能包 |
| `ACTOR_INACTIVE` | Actor 或 Agent 已被删除。它仍会列在工作空间里，记忆也仍可读取，但不能再参与写入 |
| `AGENT_OPERATION_NOT_SUPPORTED` | 该操作需要由 MemoryLake 托管运行时的 Agent：版本、复制（fork）和 A2A 只对 `INTERNAL` Agent 可用，`EXTERNAL` Agent 不支持。与 `STATE_NOT_READY` 不同，重试不会成功 |
| `TENANT_CREATION_LIMIT_REACHED` | Key 的所有者可创建的团队数已达上限 |
| `ORG_TENANT_CREATION_DISABLED` | 当前部署不支持创建团队 |
| `INTERNAL_ERROR` | 服务端意外错误 |

## 错误处理最佳实践

### 重试逻辑

```javascript
async function apiRequest(url, options, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);
      
      if (response.ok) {
        return await response.json();
      }
      
      // Don't retry 4xx errors (except 429)
      if (response.status >= 400 && response.status < 500 && response.status !== 429) {
        throw new Error(`Client error: ${response.status}`);
      }
      
      // Exponential backoff for 5xx and 429
      if (i < maxRetries - 1) {
        await sleep(Math.pow(2, i) * 1000);
        continue;
      }
    } catch (error) {
      if (i === maxRetries - 1) throw error;
      await sleep(Math.pow(2, i) * 1000);
    }
  }
}
```

### 错误日志

```javascript
try {
  const data = await apiRequest(url, options);
  return data;
} catch (error) {
  console.error('API Error:', {
    url,
    status: error.status,
    message: error.message,
    timestamp: new Date().toISOString()
  });
  throw error;
}
```
