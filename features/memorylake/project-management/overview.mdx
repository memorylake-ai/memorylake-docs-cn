## 概览

MemoryLake 用两级层级结构组织知识：**工作空间**包含**项目**。工作空间是顶层容器（您的个人空间自带一个默认工作空间；团队可以创建更多）；项目是其中聚焦的知识体——也就是您让 AI 指向的那个单元。

```text
工作空间
├── 项目 A   ← 文档 + 记忆 + Open Data + 集成
├── 项目 B
├── Agents   ← 在此工作空间中运行的 AI 助手
└── 记忆     ← 工作空间范围的记忆视图
```

## 什么是项目？

一个项目是：
- **一个检索作用域**——搜索、Playground 上下文和 Agent 召回都在项目内进行，因此上下文不会互相渗透
- **一个容器**，用于存放文档、提取的记忆和 Open Data 订阅
- **一个集成单元**——Agent 插件和 MCP Key 连接到某一个项目
- **一个权限边界**——在团队中，可以按项目授予访问权

<Note>
注册时会自动为您预置一个默认工作空间（含第一个项目）——只有当使用量增长后，您才需要显式管理这套层级结构。
</Note>

## 项目仪表盘

打开一个项目（控制台 → **工作空间** → 工作空间 → 项目）即可看到它的各个标签页：

| 标签页 | 内容 |
|---|---|
| **文件** | 已关联的文档及其处理状态；可通过上传、拖放或从文件库添加 |
| **Open Data** | 本项目订阅的精选行业数据集 |
| **记忆** | 提取的记忆——搜索、编辑、遗忘、词频视图、来源溯源 |
| **冲突** | 等待消解的矛盾记忆 |
| **集成** | 连接 Agent，以及限定在本项目范围的 API 访问 |

详见[项目仪表盘](/features/memorylake/project-management/project-dashboard)。

## 如何划分项目

- **个人**：按生活/工作上下文各建一个——"健康"、"买房"、"业余项目"。问自己：*回答关于 X 的问题时，助手是否应该引用 Y？*如果不该，就分成不同项目。
- **团队**：按项目、客户或领域各建一个——"Q3 发布"、"客户 X"、"2026 合规"。项目级权限让您可以只给某个外包人员开放一个项目。
- **开发者**：通常每个终端用户（或租户）一个项目——参见[构建带记忆的应用](/scenarios/ai-apps-with-memory)。

## 常见用例

<AccordionGroup>
<Accordion title="研究资料整理">
把论文、笔记和数据文件放进一个项目；订阅研究类 Open Data；连接您的 Agent。提问将严格基于这一语料库得到回答。
</Accordion>

<Accordion title="客户交付">
每个客户一个项目。OpenClaw 插件的按目录配置会把每个客户的工作目录固定到其对应项目——记忆绝不会跨客户流动。
</Accordion>

<Accordion title="团队知识领域">
在共享工作空间内按领域建项目（"定价"、"法务"、"入职"），并在需要处设置按项目的权限。
</Accordion>
</AccordionGroup>

## 开始使用

<Steps>
<Step title="创建项目">
在您的工作空间中创建项目，起一个清晰的名称并写明用途描述。
</Step>

<Step title="添加内容">
在文件标签页上传文件、关联已有的文件库文档、订阅 Open Data 分类。
</Step>

<Step title="对话并积累记忆">
使用限定在该项目范围的 Playground——记忆会自动提取。在记忆标签页中查看它们。
</Step>

<Step title="连接集成">
在集成标签页中安装 OpenClaw 插件，或为该项目配置 API 访问。
</Step>
</Steps>
